# EDS rooms design

Статичний Three.js / TypeScript редактор **наявного простору з Blender**. Весь будинок має габарити приблизно 49,6 × 8,47 м, площа реального полігонального контуру підлоги — 388,15 м²; переговорна кімната — 5,203635 × 6,097781 м. Геометрія походить з `reconstructed_room.blend`. Вебекспорт не змінює оригінальну архітектуру.

## Запуск і публікація

Потрібен Node.js 22.14+ лише для розробки та збірки.

```powershell
npm ci --legacy-peer-deps
npm run dev
npm run build
npm run preview
```

Локальний preview відкривається за адресою `http://127.0.0.1:4174/`.

Для хостингу завантажте **вміст `dist`**, включно з `index.html` та всією папкою `assets`. Підійдуть Cloudflare Pages, GitHub Pages, Netlify, Vercel static або звичайний HTTP-сервер. У Vite встановлено `base: './'`, тому підтримуються підкаталоги. Backend, база даних, серверний Node.js і серверна GPU не потрібні. Запуск через `file://` не підтримується браузерними завантажувачами glTF; `index.html` має обслуговуватися статичним HTTP/HTTPS-хостингом.

### GitHub Pages з вихідного коду в main

Workflow `.github/workflows/pages.yml` після кожного push у `main` встановлює залежності, запускає тести, збирає Vite, перевіряє посилання командою `node tools/verify-dist.mjs` і публікує **лише `dist`**. У Settings → Pages → Build and deployment → Source виберіть **GitHub Actions**. Адреса проєкту: `https://rrriderrr.github.io/eds-rooms-design/`. Вихідний кореневий `index.html` призначений для Vite: його не можна публікувати через «Deploy from a branch → main → /(root)» без збірки. У готовому `dist/index.html` мають бути посилання на `./assets/index-….js` та CSS, а не `/src/main.ts`.

Оригінали `assets-src`, вихідний код, інструменти та залежності не входять до артефакту Pages. Файл `public/.nojekyll` автоматично потрапляє у `dist` і також дозволяє опублікувати готовий вміст `dist` без Jekyll на іншій гілці за потреби.

Перевірка вже опублікованого сайту (звіти й знімки — у `test-results`):

```powershell
node tools/check-static-hosting.mjs --url=https://rrriderrr.github.io/eds-rooms-design/
node tools/check-deployment-interactions.mjs --url=https://rrriderrr.github.io/eds-rooms-design/
```

## Керування

**ArchViz:** WASD — рух, Shift — швидше, Пробіл — вище, C — нижче. Потягніть зображення для огляду або натисніть «Огляд мишею» для pointer lock; Esc повертає курсор. На touch-пристроях працюють віртуальний джойстик, огляд пальцем і кнопки висоти. Звичайні меблі не блокують навігацію; високі перегородки з рослинами, стіни, стеля, колони, скло й рами вікон та архітектурні двері — блокують. Перегородки перевіряються безперервно вздовж руху з радіусом камери 18 см; переміщення або видалення предмета одразу змінює перешкоду. Перевірка використовує справжні трикутники з двох боків на будь-якій висоті камери. Двері центральної кімнати відкриваються натисканням або кнопкою «Двері».

**Editor:** огляд зверху, вибір натисканням, перетягування вибраного предмета. V/G/R — вибір/переміщення/обертання, F — фокус, Delete — видалення, Ctrl+D — копія, Ctrl+Z / Ctrl+Shift+Z — історія. На touch-пристроях властивості згортаються, щоб залишити місце для перетягування. Кнопки дають ті самі дії. Прив’язка має кроки 0,5 / 0,25 / 0,05 м, обертання — 15°. Alt під час drag тимчасово вимикає сітку, Shift дає точний крок.

Картки бібліотеки можна перетягувати одразу у вибрану точку сцени. На ПК тягніть картку; на touch — ручку ⠿, решта картки зберігає прокручування. Проксі рухається в реальному часі, прилипає до підлоги, стіни або стільниці та показує зелену/червону допустимість позиції. Запис у SceneState відбувається лише після допустимого відпускання. Escape, скасування жесту й відпускання поза canvas прибирають preview без додавання предмета. Undo скасовує одне розміщення.

ПКМ на підлозі Editor відкриває «Запустити ArchViz тут»: перегляд починається у вибраній точці, з перевіркою відступу від стін і дверей. На touch-пристроях доступні звичайне перемикання режиму, джойстик і кнопки висоти.

Архітектура захищена від редагування. Шари лише змінюють видимість. Стеля прихована в Editor за замовчуванням. Настінні об’єкти прив’язуються до реальних стін; аксесуари — до поверхонь столів і тумб. Вони рухаються та обертаються разом з опорою; видалення опори приховує аксесуари, а Undo відновлює всю групу. Звичайне розміщення перевіряє межі, перетини та зону відчинення дверей. «Вільне розміщення» — явне вимкнення цих перевірок.

## Пресети і дані

Дві області мають незалежні пресети: **16 для переговорної** (`builtin-0…15`) і **8 для великого залу** (`hall-preset-0…7`). Перемикач над списком визначає, яку область змінює вибір або «Відновити цю область». Інша область зберігає свої предмети, кольори, мотиви та зміни. «Зберегти» й експорт фіксують весь простір разом; збережений власний пресет також можна застосовувати до однієї області.

У кожному пресеті залу є всі **26 вихідних столів у їхніх точних місцях**, 14 табличок і 14 повнорозмірних смуг приглушеної матової фарби біля дверей, різновиди крісел-мішків та дві корпоративні вивіски EDS — історія розвитку й Україна/відвантаження. Столи стали редагованими предметами: їх можна видаляти, переміщувати, повертати, дублювати та додавати з бібліотеки. Комбінований архітектурний дубль прихований лише у вебпредставленні. Маркерна дошка є у всіх 15 мебльованих пресетах переговорної, а коркова залишається в каталозі. `0` очищає лише переговорну.

У задній частині залу кожен пресет має **дві високі перегородки з рослинами в один прямий ряд** перед альковом дверей **15 — Вхід** та **02 — Кімната команди**. Двері **14 — Сходи** залишаються на відкритому боці залу; ряд можна вільно обійти. Шість конструкцій у бібліотеці «Перегородки»: дубовий екран, модульний зелений стелаж, решітка з ліанами, живий зелений екран, рейковий та акустичний сади. Габарит кожної — 2 × 2,3 × 0,48 м. Стелажі, решітки й зелені конструкції відкриті між листям, без прихованої стінки; тканинна панель є тільки у варіанті 1, окремі акустичні секції — у варіанті 6. Варіанти й кольори різняться між пресетами; предмети можна переміщувати, дублювати й видаляти. У старій підготовленій розстановці з чотирьох модулів кнопка **«Виправити розміщення перегородок»** змінює тільки цю групу на два модулі одним Undo, зберігаючи вибрані моделі, кольори, інші меблі й оздоблення. У чернетці без перегородок кнопка **«Додати перегородки з рослинами»** додає два модулі. При завантаженні нічого самостійно не повертається й не переміщується.

Розділ **«Оздоблення»**: виберіть стіну натисканням у Editor або зі списку, змініть фарбу, мотив і його колір або одну з восьми **повностінних композицій EDS**. «Показати цю стіну» наближає камеру. У Editor вибрана поверхня має видимий бірюзовий контур і легке тонування з відкритими дверними та віконними прорізами; підсвічування зникає поза розділом оздоблення та в ArchViz. П’ять кольорів, три мотиви й точні контури логотипа отримано з наданого `EDS_RGB_design_elements (2).svg`. Композиції поєднують великий EDS, діагональні кольорові поля та українську типографіку цінностей; усі 15 мебльованих пресетів переговорної мають одну акцентну стіну. Це шар альбедо на реальних трикутниках стіни зі збереженням PBR-рельєфу та baked GI. Внутрішня поверхня переговорної й зовнішня поверхня тієї самої стіни мають незалежні настройки. Мурали та мотиви ділять один lossless WebP-атлас 4096², близько 157 КіБ; High перевірено з лімітом 16 texture units.

Кольорові смуги біля дверей також є фарбою на штукатурці, без рамок, товщини та власних тіней. Вони залишаються редагованими елементами: колір, ширина, положення, видалення й Undo. Видимий верх автоматично обмежено нижньою гранню чорної балки: 2,65 / 3,00 / 3,05 м у залі; низ — верхом плінтуса 0,07 м. Виміри перевірено за реальними GLB-трикутниками та збережено в `assets-src/main-hall/paintable-surfaces.json`. У всіх заготовлених пресетах таблички розташовані по центру кольорових смуг; назви й номери є тільки на табличках. Колір друку на прозорому PMMA автоматично узгоджується з фоном; зайвих логотипів на табличках немає. Надписи мають правильну орієнтацію на всіх напрямках стін. Старі змінені та власні дизайни зберігають свої предмети й оздоблення; нову композицію в них можна вибрати через «Оздоблення» без скидання пресета.

Таблички у готових пресетах містять **номери та погоджені позначення «Вихід» / «WC»**, без EDS або декоративних підписів. У редакторі залишається довільний текст: багаторядкове поле до 500 символів, явні порожні рядки, автоматичний перенос і підбір розміру. Текст зберігається у пресеті, Undo/Redo, експорті й IndexedDB. За замовчуванням на табличці 14 написано «Вихід», на 10 і 15 — «WC», на решті — номери. Смуги мають окрему бліду палітру пігментної фарби; точні корпоративні RGB збережено для друкованих вивісок і тканин. Три варіанти корпусу: прозорий PMMA на дистанційних кріпленнях за RIGA A6, матований метал і корпоративна касета.

Каталог містить **115 позитивних варіантів моделей**. Шість оригінальних вивісок за фотографіями залишаються в бібліотеці. Готові пресети великого залу використовують лише **EDS · Історія розвитку** та **EDS · Україна та відвантаження**, по **8 окремих дизайнів** кожної композиції. Змінюються сітка, типографічна ієрархія, розміщення карти й показників, колірні поля та корпоративні мотиви. Точний фірмовий логотип і п’ять кольорів отримано з вихідного EDS SVG. Контур України з Кримом, рельєф областей, 15 історичних подій і 7 показників збережено. Показники мають конструкцію для заміни: 23 окремі пластикові картки у напрямних (дизайни 1/4/6), плоскі магнітні цифри на сталі (2/7) або сім окремих матових e-ink модулів із рамками (3/5/8). Історичні дати залишаються постійним друком. Кожна вивіска — один предмет; усі літери й контури мають власну геометрію. Старий малорозбірливий текст історії раніше реконструйовано, а не оголошено точним OCR.

Подвійні стіни переговорної при завантаженні об’єднуються у дві замкнуті товсті оболонки без внутрішніх граней і повітряних порожнин. Збережено внутрішні розміри, зовнішні площини, прорізи та семантичні поверхні для фарби. Перебудовані грані мають спільні метричні UV та неперервне освітлення, обчислене з вихідних baked probes у світових координатах. Старі карти UV1 цих тонких оболонок більше не змішуються з новими поверхнями. Навігація враховує заповнені об’єми. В Editor автоприховування працює для всієї товстої стіни разом із торцями, верхньою смугою і контуром; стороння оболонка не залишається висіти. Товщина продовжується до стелі 4,32 м; на зовнішніх гранях темний пояс починається на спільній висоті 3 м без накладних коробів. Темні частини фасаду входу починаються на спільній позначці 3 м; світлі та темні ділянки отримують узгоджене PBR/пробне освітлення. Джерельні GLB і Blender збережені, корекція геометрії детерміновано виконується для обох вебрежимів.

Шість **настінних годинників без корпусу** мають окремі цифри, поділки й стрілки; роль циферблата виконує справжня штукатурка. У кожному пресеті залу є свій варіант на `wall-12` / `Wall_12_Clean` — стіні, визначеній променем із поточного viewport Blender 28.10.2026. Стрілки показують місцевий час пристрою без сервера; цифри прилягають до стіни. Старі круглі годинники залишаються в бібліотеці.

Телевізор 85″ (1,90 × 1,10 м) установлено навпроти дивана у пресетах 3, 6, 9 і 13. Розстановку 6 перероблено; напрямки стільців і ноутбуків виправлено по всьому набору. Деталі — `docs/layout-review.md`. Незмінена чернетка вбудованого пресета отримує оновлену конфігурацію при новій версії сайту; змінені та користувацькі дизайни зберігаються без підміни.

IndexedDB зберігає користувацькі дизайни та чернетку між перезавантаженнями. LocalStorage містить лише невеликі налаштування. Експорт `.archpreset.json` включає конфігурацію без моделей і текстур. Імпорт перевіряє розмір, версію, project ID, asset IDs, типи, діапазони, стіни і скінченні числа; не виконує код. Передбачено міграцію старої схеми. Разова позначка `doorLabelRevision: 1` замінює лише старі штатні номери 10/14/15; довільні власні надписи зберігаються. Разова позначка `hallDecorRevision: 1` застосовує погоджене оновлення старих вивісок і номерів лише до залу, зберігаючи інші предмети, їхні координати, оздоблення й стан переговорної. Після оновлення власний текст табличок і видалені користувачем предмети не повертаються при завантаженні.

```typescript
{
  schemaVersion: 2,
  projectId: 'polycam-lounge-room',
  roomId: 'lounge-room-01',
  presetId: 'user-…', name: 'Мій дизайн',
  createdAt: '…', updatedAt: '…',
  objects: [{ id: '…', assetId: 'sofa', variant: 1, material: 'oat',
    position: [0, 0, 0], rotation: 0, regionId: 'meeting' }],
  regionPresets: { meeting: { presetId: 'builtin-1', basePresetId: 'builtin-1', modified: true },
    hall: { presetId: 'hall-preset-0', basePresetId: 'hall-preset-0', modified: false } },
  wallFinishes: { west: { color: null, motif: 0, accent: '#a2b8fe', mural: 1 } },
  doorOpen: false, layers: { /* видимість категорій */ }
}
```

`SceneStore` — джерело істини. Three.js-об’єкти є лише візуальним представленням. Редаговані предмети мають стабільні asset IDs, production/proxy references, габарити, варіанти, правила поверхонь і curated materials.

## Графіка

Основний шлях — WebGL 2. Без нього показується статичний Cycles-ракурс з поясненням. WebGPU, SSGI, realtime GI та ray tracing не потрібні.

Статична архітектура має **Cycles indirect-only GI**, очищене offline через OpenImageDenoise, окремі UV1 та HDR lightmaps: 2K центральна кімната, 4K/2K/1K повний простір. Змінні меблі не впечені в lightmap: вони використовують 18 виміряних irradiance probes, PMREM і 25 нерухомих direct lights на місцях справжніх світильників. Позиція камери не змінює їхню яскравість або розташування. High має шість карт динамічних тіней 2048², SSR на підлозі, SSAO, 4× MSAA та SMAA; Medium — дві карти тіней 2048² і 2× MSAA. Тіні оновлюються при зміні меблів або дверей. Low зберігає ті самі baked GI та direct lights. Якість вимірює frame time й коригує render scale, DPR, тіні, AO, відбиття, mip-рівні та LOD. Прохід SSR додає лише відбиття поверх основного зображення; окремий single-sample depth target не може підмінити непрозору архітектуру панорамою.

Дрібні горизонтальні смуги на світлих стінах були самозатіненням ширококутних світильників. Масштаб Quixel-текстур і вихідні UV0 залишено метричними. Точність карт тіней, радіус PCF 1,5, near 0,3 м та невелике зміщення перевірено на справжніх стінах зблизька; динамічні тіні меблів збережено. Повторна перевірка: `node tools/check-wall-shadows.mjs`.

Підлога має діелектричне матове покриття Quixel: roughness ORM приблизно 0,90, metalness 0. SSR підлоги розмито й обмежено 4%, щоб не створювати дзеркальних копій меблів. Круглі production-деталі мають плавний силует і фаски; proxy залишаються легкими. Каркаси, підніжки, спинки та кріплення проходять геометричні тести реальних контактів і видимості поверхонь.

За вікнами — повносферичний фон фабричного цеху за мотивами наданого фото; він не змінює виміряне приміщення. Editor його не показує. Скло прозоре з окремими PMREM-відбиттями; віконні рами білі. Нижче наведено точне походження панорами та межі її HDR-даних.

## Ресурси та pipeline

* `src/core` — схема, історія, розміщення, реальні поверхні та збереження.
* `src/catalog` — єдиний каталог, процедурні моделі/проксі, 16 пресетів.
* `src/graphics` — захищена архітектура, освітлення, FPS, renderer.
* `src/assets` — KTX2/Basis, матеріали та керування ресурсами.
* `public/assets` — лише вебресурси: GLB, KTX2, HDR, manifests, прев’ю та локальні decoders.
* `assets-src` — Blender-копії, metadata, provenance та звіти. Не потрапляє у `dist`.
* `tools` — повторювані експорт, bake, оптимізація, імпорт реальних моделей та QA.
* `tests`, `test-results` — семантичні та браузерні перевірки/знімки.

Важкі завантаження та проміжні файли зберігаються в `E:/ArchViz_Resources`, а не в тимчасових каталогах C. `ARCHVIZ_RESOURCES` налаштовує material/model tools. Blender-скрипти цього workstation використовують той самий каталог E; перед перенесенням на інший комп’ютер перевірте їхні `WORK` paths.

Чотири поверхні отримано з уже наявної бібліотеки **Fab / Quixel**: Painted Plaster `pjBoU0` для стін, Smooth Concrete `tezmdjno` для спокійного сірого покриття підлоги, Oak Veneer `tfjcffgc` для меблів і Painted Metal Door `ugzobcglw` для деталей фарбованого металу. Тканина — локальний Quixel Furniture Fabric `sjfvce3c`. Реальні рослини та частина крісел/стільців — Poly Haven CC0; інші моделі створено для проєкту. Походження й ліцензії записано окремо, без підміни CC0 ресурсів назвою Quixel. Native Epic Games Launcher / Fab працює через Computer Use; ці чотири матеріали були позначені як збережені в бібліотеці до завантаження. Покупок, нових логінів чи угод не було. Оригінали й проміжні файли — на `E:/ArchViz_Resources`, у `dist` лише оптимізовані карти. Деталі: `tools/MATERIALS.md`, `assets-src/materials/overrides.json`, `source_missing.json` і `real-models.json`.

За вікнами використано повносферичну 360° панораму цеху, створену ImageGen за видимими на фото ознаками. Вона не є виміряним HDR: manifest прямо вказує LDR → linear RGBE. Скло має окреме PMREM-відбиття панорами; baked GI кімнати й внутрішнє середовище залишаються окремими. Повторна підготовка: `node tools/prepare-factory-panorama.mjs`.

```powershell
npm run assets                         # KTX2, ORM packing, mipmaps, Meshopt
npm run assets:real                    # локальні легально отримані scan-моделі → web LODs
npm run export:catalog                 # каталог; production overrides зберігаються
npm run assets:blender                 # editable незжаті копії GLB на E
npm run export:blender                 # snapshot MCP → room + full space + GI + web exports
python tools/reexport_room.py --concepts    # також Blender-концепції та контрольні рендери
```

`export:catalog` автоматично приєднує print-atlas вивісок до GLB перед Meshopt-оптимізацією. Не треба вручну повторювати крок прикріплення друку. Concepts будуються лише з підготовленого `assets-src/room_archviz.blend`; скрипт відхиляє випадковий запуск на нецентрованому live-файлі та перевіряє рендери на порожнє/чорне зображення.

`tools/MATERIALS.md` описує підміну source через overrides. KTX2 вибирає GPU-формат через capability detection; локальні WebP/PNG fallback не потребують CDN. Source maps мають правильне sRGB/linear розділення, UV0 у метрах, ORM на UV0, lightmap на UV1. Моделі оптимізовані Meshopt. Реальні скани мають окремі geometry LODs; активні варіанти завантажуються за потребою, кеш обмежується.

## Перевірки

```powershell

npm run build
$env:PLAYWRIGHT_BROWSERS_PATH='E:\ArchViz_Resources\tools\playwright'
npx playwright install chromium firefox webkit
npm run test:e2e
```

Playwright перевіряє Chromium desktop/phone/landscape, Firefox desktop та WebKit tablet. Функціональні сценарії використовують Medium, щоб відокремити перевірку UI від GPU-бенчмарку; High перевіряється окремими діагностичними кадрами. `tools/diagnose-render.mjs` зберігає порівняння SSR / SSAO / shadows, помилки та фактичний GL renderer. На цьому Windows-комп’ютері Chromium-тести використовують D3D11 на справжній GPU; кеш тестових браузерів зберігається на E. Software-renderer у headless-браузері не є оцінкою FPS відеокарти користувача. Звіти містяться в `test-results`.

Оригінальні 766 об’єктів перевірені за mesh/transform/parent/material fingerprints; `assets-src/analysis/full_scene_preservation_audit.json` фіксує відсутність змін. Докладні authoring-параметри — у `tools/BLENDER_PIPELINE.md`.

## Перше завантаження та підготовка графіки

До відкриття ArchViz застосунок завантажує активні моделі, матеріали й освітлення, передає текстури до GPU, виконує асинхронну компіляцію шейдерів і реальні підготовчі кадри з тінями та постобробкою. Екран показує назву поточного етапу (зокрема «Компіляція шейдерів»), прогрес-бар і відсоток 0–100. Значення змінюються після виконання роботи; таймер не імітує прогрес. Відсоток означає частку завершених етапів підготовки, а не прогноз часу в секундах. 100% і зняття блокування настають після готовності першого кадру.

У режимі «Авто» вибір початкової якості також відбувається під завантажувачем; ручний вибір зберігається. Початковий Editor готує легку геометрію, а перший перехід до ArchViz окремо завершує підготовку production-графіки. Зміни чернетки й перемикання пресетів заблоковані лише на час цього етапу. Розстановка, оздоблення та обраний пресет не скидаються. Підготовка охоплює поточну сцену; нові предмети з бібліотеки завантажуються після їх додавання. Усе працює на статичному хостингу.

Фактичні перевірки з новими профілями браузера й вимкненими Chromium HTTP/shader cache:

```powershell
node tools/check-startup-readiness.mjs
node tools/check-startup-transition.mjs
node tools/check-static-hosting.mjs
```

Звіти й скриншоти: `test-results/startup-readiness`, `test-results/startup-transition`. Для WebKit використано свіжий процес і контекст. Перевірено завершення 0→100%, перші 12 напрямків камери, відсутність нових shader programs/GPU-текстур і пізніх 3D-запитів, а також збереження конфігурації при першому переході Editor→ArchViz. Тривалість підготовки залежить від пристрою, сцени та мережі.


## Окремі корпоративні мотиви EDS

В Editor відкрийте «Оздоблення», виберіть стіну й додайте потрібний мотив. Кожне натискання створює окремий шар: на одній стіні можна розмістити до 64 мотивів, зокрема однакових. Вибраний мотив має власну зелену рамку й маркери. Перетягування зберігає точку захоплення; у властивостях доступні ширина, висота, поворот у площині стіни, колір і непрозорість. Порядок списку та кнопки «На передній план» / «На задній план» визначають накладання. Копіювання, видалення та зміна порядку підтримують Undo/Redo. Мотиви також можна перетягувати з бібліотеки з живим попереднім переглядом; Escape скасовує додавання.

Мотиви залишаються фарбою на самій штукатурці: вони не створюють навісних панелей, не перекривають отвори та верхню сталеву частину. Вибір у прозорих проміжках пропускає курсор до видимого мотиву під ними. Стара одиночна настройка мотиву перетворюється в окремий елемент із тим самим виглядом; чернетки, меблі й обрані дизайни не скидаються. Розміри, шари та інші властивості зберігаються в користувацькому пресеті й переносному JSON.

Каталог містить 12 мотивів і 16 повностінних композицій. Нові форми побудовані з векторних елементів наданого EDS SVG. Попередні 3 SVG мотивів і 8 SVG композицій збережені без змін. Вісім нових композицій розподілені між пресетами переговорної 8–15. Об’ємний логотип EDS додано до пресетів залу 1, 4, 6 і 7; початкові столи, дві головні вивіски й доступ до дверей збережені. Походження «з фотографій» більше не додається до назв каталогу.

```powershell
node tools/prepare-wall-murals.mjs          # також готує бібліотеку мотивів
node tools/check-corporate-motifs.mjs       # реальні UI, пікселі, High, сховище, Chromium/WebKit/phone
node tools/check-motif-pointer.mjs          # справжнє перетягування, шари та скасування
node tools/check-hall-volume-logos.mjs      # чотири пресети, реальна товщина логотипів
```

Нові ресурси та функції готуються локально; вони не потребують бекенду. Атлас усіх зображень залишається 4096×4096. На ПК порядок окремих мотивів передається через маленьку GPU-текстуру даних; у High із шістьма джерелами тіней фактично перевірено не більше 15 фрагментних семплерів. Перевірки та скриншоти: `test-results/corporate-motifs`, `test-results/motif-pointer`, `test-results/hall-volume-logos`.


## Сумісність роспису стін із мобільною графікою

На сенсорних пристроях і GPU з малим бюджетом uniform-параметрів роспис обох боків стіни збирається в звичайну RGBA8-текстуру під час початкової підготовки. Матеріал штукатурки, фізичне освітлення, тіні, отвори, композиції та редаговані шари зберігаються. Шейдер не потребує Float32-таблиці шарів і великого циклу малювання. Після редагування оновлюється лише відповідна текстура. Чисті стіни не отримують великого зображення.

Початкова підготовка також перевіряє фактичне компонування програм стін: якщо драйвер відхилив складний варіант, сумісний варіант компілюється до закриття екрана завантаження. Перевірка: `node tools/check-mobile-wall-paint.mjs`; опції `--url=` і `--out=` дозволяють перевіряти опубліковану збірку. Це перевірки браузерних профілів та відмови компілятора; вони не замінюють перевірку на фізичному телефоні.
