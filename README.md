# EDS rooms design

Статичний Three.js / TypeScript редактор **наявного простору з Blender**. Весь будинок має габарити приблизно 49,6 × 8,47 м, площа реального полігонального контуру підлоги — 388,15 м²; основна лаунж-кімната — 5,203635 × 6,097781 м. Геометрія походить з `reconstructed_room.blend`. Вебекспорт не змінює оригінальну архітектуру.

## Запуск і публікація

Потрібен Node.js 22.14+ лише для розробки та збірки.

```powershell
npm ci --legacy-peer-deps
npm run dev
npm run build
npm run preview
```

Локальний preview відкривається за адресою `http://127.0.0.1:4174/`.

Для хостингу завантажте **вміст `dist`**, включно з `index.html` та всією папкою `assets`. Підійдуть Cloudflare Pages, GitHub Pages, Netlify, Vercel static або звичайний HTTP-сервер. У Vite встановлено `base: './'`, тому підтримуються підкаталоги. Backend, база даних, серверний Node.js і серверна GPU не потрібні. Запуск через `file://` не підтримується браузерними завантажувачами glTF; `index.html` має обслуговуватися статичним HTTP/HTTPS-хостингом.

### GitHub Pages з вихідного коду в main

Workflow `.github/workflows/pages.yml` після кожного push у `main` встановлює залежності, запускає тести, збирає Vite, перевіряє посилання командою `node tools/verify-dist.mjs` і публікує **лише `dist`**. У Settings → Pages → Build and deployment → Source виберіть **GitHub Actions**. Адреса проєкту: `https://rrriderrr.github.io/eds-rooms-design/`. Вихідний кореневий `index.html` призначений для Vite: його не можна публікувати через «Deploy from a branch → main → /(root)» без збірки. У готовому `dist/index.html` мають бути посилання на `./assets/index-….js` та CSS, а не `/src/main.ts`.

Оригінали `assets-src`, вихідний код, інструменти та залежності не входять до артефакту Pages. Файл `public/.nojekyll` автоматично потрапляє у `dist` і також дозволяє опублікувати готовий вміст `dist` без Jekyll на іншій гілці за потреби.

## Керування

**ArchViz:** WASD — рух, Shift — швидше, Пробіл — вище, Ctrl — нижче. Потягніть зображення для огляду або натисніть «Огляд мишею» для pointer lock; Esc повертає курсор. На touch-пристроях працюють віртуальний джойстик, огляд пальцем і кнопки висоти. Меблі не блокують навігацію; стіни, стеля, колони, скло й рами вікон та архітектурні двері — блокують. Перевірка використовує справжні трикутники з двох боків на будь-якій висоті камери. Двері центральної кімнати відкриваються натисканням або кнопкою «Двері».

**Editor:** огляд зверху, вибір натисканням, перетягування вибраного предмета. V/G/R — вибір/переміщення/обертання, F — фокус, Delete — видалення, Ctrl+D — копія, Ctrl+Z / Ctrl+Shift+Z — історія. На touch-пристроях властивості згортаються, щоб залишити місце для перетягування. Кнопки дають ті самі дії. Прив’язка має кроки 0,5 / 0,25 / 0,05 м, обертання — 15°. Alt під час drag тимчасово вимикає сітку, Shift дає точний крок.

Картки бібліотеки можна перетягувати одразу у вибрану точку сцени. На ПК тягніть картку; на touch — ручку ⠿, решта картки зберігає прокручування. Проксі рухається в реальному часі, прилипає до підлоги, стіни або стільниці та показує зелену/червону допустимість позиції. Запис у SceneState відбувається лише після допустимого відпускання. Escape, скасування жесту й відпускання поза canvas прибирають preview без додавання предмета. Undo скасовує одне розміщення.

ПКМ на підлозі Editor відкриває «Запустити ArchViz тут»: перегляд починається у вибраній точці, з перевіркою відступу від стін і дверей. На touch-пристроях доступні звичайне перемикання режиму, джойстик і кнопки висоти.

Архітектура захищена від редагування. Шари лише змінюють видимість. Стеля прихована в Editor за замовчуванням. Настінні об’єкти прив’язуються до реальних стін; аксесуари — до поверхонь столів і тумб. Вони рухаються та обертаються разом з опорою; видалення опори приховує аксесуари, а Undo відновлює всю групу. Звичайне розміщення перевіряє межі, перетини та зону відчинення дверей. «Вільне розміщення» — явне вимкнення цих перевірок.

## Пресети і дані

Вбудовані пресети `0…15` незмінні; `0` — вихідна порожня лаунж-кімната. Існуючі столи в інших частинах будинку залишаються частиною вихідного простору. Позитивні пресети мають незалежні предмети, а не монолітні GLB. Варіант `0 / Немає` завжди означає відсутність предмета. Редагування створює стан «Змінено»; «Відновити пресет» повертає вбудовану конфігурацію.

Каталог містить 75 позитивних model variants, зокрема шість вивісок за фотографіями. П’ять різних коридорних композицій присутні в кожному пресеті між реальними дверима стіни `wall-38`; товстий логотип EDS використано також у частині лаунж-пресетів. Кожна багатокомпонентна вивіска редагується як один предмет. Точні контури карт, окремі акрилові панелі, chrome-літери та дерев’яний рельєф мають власну геометрію; розміри відновлено відносно дверей і стін. Дрібний нерозбірливий текст timeline реконструйовано, а не оголошено точним OCR. Подробиці — `assets-src/signage/README.md`.

Телевізор 85″ (1,90 × 1,10 м) установлено навпроти дивана у пресетах 3, 6, 9 і 13. Розстановку 6 перероблено; напрямки стільців і ноутбуків виправлено по всьому набору. Деталі — `docs/layout-review.md`. Незмінена чернетка вбудованого пресета отримує оновлену конфігурацію при новій версії сайту; змінені та користувацькі дизайни зберігаються без підміни.

IndexedDB зберігає користувацькі дизайни та чернетку між перезавантаженнями. LocalStorage містить лише невеликі налаштування. Експорт `.archpreset.json` включає конфігурацію без моделей і текстур. Імпорт перевіряє розмір, версію, project ID, asset IDs, типи, діапазони, стіни і скінченні числа; не виконує код. Передбачено міграцію старої схеми.

```typescript
{
  schemaVersion: 1,
  projectId: 'polycam-lounge-room',
  roomId: 'lounge-room-01',
  presetId: 'user-…', name: 'Мій дизайн',
  createdAt: '…', updatedAt: '…',
  objects: [{ id: '…', assetId: 'sofa', variant: 1, material: 'oat',
    position: [0, 0, 0], rotation: 0 }],
  doorOpen: false, layers: { /* видимість категорій */ }
}
```

`SceneStore` — джерело істини. Three.js-об’єкти є лише візуальним представленням. Редаговані предмети мають стабільні asset IDs, production/proxy references, габарити, варіанти, правила поверхонь і curated materials.

## Графіка

Основний шлях — WebGL 2. Без нього показується статичний Cycles-ракурс з поясненням. WebGPU, SSGI, realtime GI та ray tracing не потрібні.

Статична архітектура має **Cycles indirect-only GI**, очищене offline через OpenImageDenoise, окремі UV1 та HDR lightmaps: 2K центральна кімната, 4K/2K/1K повний простір. Змінні меблі не впечені в lightmap: вони використовують 18 виміряних irradiance probes, PMREM і 25 нерухомих direct lights на місцях справжніх світильників. Позиція камери не змінює їхню яскравість або розташування. High має шість карт динамічних тіней, SSR на підлозі, SSAO, 4× MSAA та SMAA; Medium — дві карти тіней і 2× MSAA. Тіні оновлюються при зміні меблів або дверей. Low зберігає ті самі baked GI та direct lights. Якість вимірює frame time й коригує render scale, DPR, тіні, AO, відбиття, mip-рівні та LOD. Прохід SSR додає лише відбиття поверх основного зображення; окремий single-sample depth target не може підмінити непрозору архітектуру панорамою.

Підлога має діелектричне матове покриття Quixel: roughness ORM приблизно 0,90, metalness 0. SSR підлоги розмито й обмежено 4%, щоб не створювати дзеркальних копій меблів. Круглі production-деталі мають плавний силует і фаски; proxy залишаються легкими. Каркаси, підніжки, спинки та кріплення проходять геометричні тести реальних контактів і видимості поверхонь.

За вікнами — повносферичний фон фабричного цеху за мотивами наданого фото; він не змінює виміряне приміщення. Editor його не показує. Скло прозоре з окремими PMREM-відбиттями; віконні рами білі. Нижче наведено точне походження панорами та межі її HDR-даних.

## Ресурси та pipeline

* `src/core` — схема, історія, розміщення, реальні поверхні та збереження.
* `src/catalog` — єдиний каталог, процедурні моделі/проксі, 16 пресетів.
* `src/graphics` — захищена архітектура, освітлення, FPS, renderer.
* `src/assets` — KTX2/Basis, матеріали та керування ресурсами.
* `public/assets` — лише вебресурси: GLB, KTX2, HDR, manifests, прев’ю та локальні decoders.
* `assets-src` — Blender-копії, metadata, provenance та звіти. Не потрапляє у `dist`.
* `tools` — повторювані експорт, bake, оптимізація, імпорт реальних моделей та QA.
* `tests`, `test-results` — семантичні та браузерні перевірки/знімки.

Важкі завантаження та проміжні файли зберігаються в `E:/ArchViz_Resources`, а не в тимчасових каталогах C. `ARCHVIZ_RESOURCES` налаштовує material/model tools. Blender-скрипти цього workstation використовують той самий каталог E; перед перенесенням на інший комп’ютер перевірте їхні `WORK` paths.

Чотири поверхні отримано з уже наявної бібліотеки **Fab / Quixel**: Painted Plaster `pjBoU0` для стін, Smooth Concrete `tezmdjno` для спокійного сірого покриття підлоги, Oak Veneer `tfjcffgc` для меблів і Painted Metal Door `ugzobcglw` для деталей фарбованого металу. Тканина — локальний Quixel Furniture Fabric `sjfvce3c`. Реальні рослини та частина крісел/стільців — Poly Haven CC0; інші моделі створено для проєкту. Походження й ліцензії записано окремо, без підміни CC0 ресурсів назвою Quixel. Native Epic Games Launcher / Fab працює через Computer Use; ці чотири матеріали були позначені як збережені в бібліотеці до завантаження. Покупок, нових логінів чи угод не було. Оригінали й проміжні файли — на `E:/ArchViz_Resources`, у `dist` лише оптимізовані карти. Деталі: `tools/MATERIALS.md`, `assets-src/materials/overrides.json`, `source_missing.json` і `real-models.json`.

За вікнами використано повносферичну 360° панораму цеху, створену ImageGen за видимими на фото ознаками. Вона не є виміряним HDR: manifest прямо вказує LDR → linear RGBE. Скло має окреме PMREM-відбиття панорами; baked GI кімнати й внутрішнє середовище залишаються окремими. Повторна підготовка: `node tools/prepare-factory-panorama.mjs`.

```powershell
npm run assets                         # KTX2, ORM packing, mipmaps, Meshopt
npm run assets:real                    # локальні легально отримані scan-моделі → web LODs
npm run export:catalog                 # каталог; production overrides зберігаються
npm run assets:blender                 # editable незжаті копії GLB на E
npm run export:blender                 # snapshot MCP → room + full space + GI + web exports
python tools/reexport_room.py --concepts    # також Blender-концепції та контрольні рендери
```

`export:catalog` автоматично приєднує print-atlas вивісок до GLB перед Meshopt-оптимізацією. Не треба вручну повторювати крок прикріплення друку. Concepts будуються лише з підготовленого `assets-src/room_archviz.blend`; скрипт відхиляє випадковий запуск на нецентрованому live-файлі та перевіряє рендери на порожнє/чорне зображення.

`tools/MATERIALS.md` описує підміну source через overrides. KTX2 вибирає GPU-формат через capability detection; локальні WebP/PNG fallback не потребують CDN. Source maps мають правильне sRGB/linear розділення, UV0 у метрах, ORM на UV0, lightmap на UV1. Моделі оптимізовані Meshopt. Реальні скани мають окремі geometry LODs; активні варіанти завантажуються за потребою, кеш обмежується.

## Перевірки

```powershell
npm test
npm run build
$env:PLAYWRIGHT_BROWSERS_PATH='E:\ArchViz_Resources\tools\playwright'
npx playwright install chromium firefox webkit
npm run test:e2e
```

Playwright перевіряє Chromium desktop/phone/landscape, Firefox desktop та WebKit tablet. Функціональні сценарії використовують Medium, щоб відокремити перевірку UI від GPU-бенчмарку; High перевіряється окремими діагностичними кадрами. `tools/diagnose-render.mjs` зберігає порівняння SSR / SSAO / shadows, помилки та фактичний GL renderer. На цьому Windows-комп’ютері Chromium-тести використовують D3D11 на справжній GPU; кеш тестових браузерів зберігається на E. Software-renderer у headless-браузері не є оцінкою FPS відеокарти користувача. Звіти містяться в `test-results`.

Оригінальні 766 об’єктів перевірені за mesh/transform/parent/material fingerprints; `assets-src/analysis/full_scene_preservation_audit.json` фіксує відсутність змін. Докладні authoring-параметри — у `tools/BLENDER_PIPELINE.md`.
